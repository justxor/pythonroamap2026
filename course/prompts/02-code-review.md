# 🔍 Промпт 02 — Code review

> Используй когда: написал диф / собираешься открыть PR / ревьюишь чужой PR.

---

```
[CONTEXT]
Python 3.13, стек: FastAPI + SQLAlchemy 2.x async + Pydantic v2 + structlog.
Стиль зафиксирован в CLAUDE.md / .cursorrules.
Я работаю в команде, PR пойдёт на ревью.

[DIFF]
[ВСТАВЬ DIFF ИЛИ ФАЙЛЫ ЦЕЛИКОМ]

[TASK]
Проведи ревью этого кода как старший Python-разработчик.

[RULES] Проверь:
1) Корректность — есть ли логические ошибки, race conditions, off-by-one.
2) Безопасность — SQL-injection, command injection, секреты в коде, eval/shell=True, небезопасный YAML.
3) Производительность — N+1 запросы, неэффективные циклы, ненужные allocations.
4) Качество — нарушения SOLID, дублирование, плохие имена, magic numbers.
5) Стиль — type hints (нет Any/cast), pyright --strict, ruff правила.
6) Тестируемость — есть ли скрытые зависимости, hardcoded I/O.
7) Тесты — покрыты ли изменения, не сломаны ли существующие сценарии.

[LENS]
Для каждой находки укажи:
- 🔴 Critical / 🟡 Major / 🟢 Nit
- Файл:строка
- Что не так (1-2 предложения)
- Как исправить (код-сниппет, если короткий)

В конце — общий вердикт: approve / request changes / needs discussion.
```

---

### 💡 Когда применять
- Перед `gh pr create` — самопроверка.
- Когда тебе пришёл большой PR на ревью — пройди им сначала, потом своими глазами по топ-findings.
