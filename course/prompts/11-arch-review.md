# 🏗️ Промпт 11 — Архитектурное ревью

> Используй когда: проект растёт, появляется ощущение «всё связано со всем».

---

```
[CONTEXT]
Python 3.13. Проект: <короткое описание домена>.
Текущая структура (вывод tree -L 3):
[ВСТАВЬ ДЕРЕВО ПАПОК]

Ключевые модули и их зависимости:
[ВСТАВЬ ОПИСАНИЕ — кто кого импортирует]

[TASK]
Проведи архитектурное ревью с прицелом на гексагональную архитектуру / DDD (stage-13 курса).

[RULES] Оцени:
1) **Слои** — есть ли разделение domain / application / infrastructure / interfaces.
2) **Направление зависимостей** — домен не должен импортировать инфраструктуру.
3) **Use-cases** — выделены ли явно или растворены в контроллерах.
4) **Порты-адаптеры** — есть ли Protocol-интерфейсы для внешних зависимостей.
5) **Транзакционные границы** — где Unit of Work, нет ли «висящих» коммитов.
6) **Events / Outbox** — как публикуются доменные события.
7) **Тестируемость** — можно ли запустить домен без БД и HTTP.

[LENS]
1) **Текущая картина** — диаграмма зависимостей (ASCII) и слабые места.
2) **Целевая картина** — как должно выглядеть после рефакторинга.
3) **План миграции** — упорядоченные шаги, каждый — отдельный PR.
4) **Риски** — что может сломаться, как это поймать (тесты, фиче-флаги).
5) **Что НЕ трогать** — куда стрелять не надо.
```
