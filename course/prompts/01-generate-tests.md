# 🧪 Промпт 01 — Сгенерировать pytest-тесты

> Используй когда: написал функцию/класс, нужны качественные параметризованные тесты с покрытием граничных случаев.

---

```
[CONTEXT]
Python 3.13, проект использует pytest + pytest-asyncio + hypothesis.
Стиль: type hints обязательно, pyright --strict.
Файл: <путь/до/модуля.py>
Я работаю над: <короткое описание модуля и его роли в проекте>

[CODE]
[ВСТАВЬ КОД ФУНКЦИИ/КЛАССА ЦЕЛИКОМ]

[TASK]
Напиши pytest-тесты для этого кода.

[RULES]
- Имена тестов: test_<что>_<когда>_<ожидаем>.
- Параметризация (@pytest.mark.parametrize) для всех вариантов входа.
- Покрой:
  * happy path (нормальный сценарий);
  * граничные значения (0, -1, пусто, максимум);
  * ошибочные пути (исключения через pytest.raises с match);
  * для async — @pytest.mark.asyncio.
- 1 hypothesis-тест на инвариант (если применимо).
- Никаких реальных БД/HTTP — мокай через monkeypatch или AsyncMock.
- Type hints на параметрах и возвращаемых значениях фикстур.

[LENS]
1) Сначала перечисли список тест-кейсов (one-liner каждый), которые ты собираешься написать.
2) Жду моего «ок» — потом пишешь код в одном блоке.
3) В конце — команда запуска: \`uv run pytest tests/test_*.py -v\`.
```

---

### 🔁 Анти-паттерны, которые этот промпт исключает
- Тесты «всё в одном test_main()».
- Моки без проверки call_args.
- Игнорирование async-сценариев.
- Отсутствие негативных кейсов.
